# Rakuten Combine Batch Standalone v1.6.0 — false-positive Details guard

**Base:** `Rakuten_Combine_Batch_Standalone_v1.5.0`. This update does not touch BrandForge or Rakuten Converter Electron v2.

## Root causes corrected

1. v1.5.0 stopped its source-image OCR after finding a color caption in the bottom band. A Details image could say `BLACK` in the bottom half but `MATERIAL` or `DETAILS` in the top half and be wrongly counted as Line Up. **Fix:** full source-image OCR is always performed; detail cues override accidental color words.
2. v1.5.0 automatically accepted 4+ similar white-background silhouettes, even without color labels. Product feature/angle images can be almost identical. **Fix:** silhouettes and 2/4 cuts are supporting signals only. No silhouette-only automatic Line Up.
3. Generic HTML label `Color` was counted as a valid caption. **Fix:** actual distinct color names or coded colorway captions are required.
4. Some source `COLOR VARIATION` headings extended beyond the real color images. **Fix:** OCR-supplied Details cues truncate or veto those intervals.
5. Numbered Japanese colorway `7. シルバードーン/ホワイト` had been missed. **Fix:** stricter structured parsing accepts unknown named shades alongside recognized colors within a numbered combination.

## Behavior

- Details detected inside a previously believed lineup are routed to Details.
- Group scanning keeps source order and supports a creative prefix (up to two leading images), as in v1.5.0.
- Retains Japanese/English OCR, cut layout analysis, single source URL, HTML and 600px JPEG outputs, optional Single, editable `LINEUP COUNT`, 28px DETAILS heading and portable Electron build.
- No Original source image is saved/edited. The JPEG is still generated by screenshot, and HTML uses original image URLs.
- If no confirmed Line Up is found, all images go to Details and the row is REVIEW. This deliberately favors false negatives over publishing Details in Line Up.
- `BATCH_REPORT.json` now includes compact per-image classification evidence and method for QC.

## Changed code

- `src/core/imageOcr.js`: always OCR full image, read cut tiles and reuse fetched image bytes for shape comparison.
- `src/core/colorCaption.js`: detail cue detection expanded, numbered mixed Japanese brand colors handled.
- `src/core/variationClassifier.js`: conservative caption-confirmed grouping, reject details cues, no silhouette-only fallback, conditional source-heading truncation, shape break detection and per-image audit.
- `src/core/batch.js`: method, evidence, version and updated classification policy in output report.
- `test/batch.test.js`, `test/ocr-classifier.test.js`: revised tests for safer behavior.
- `test/false-positive-guard.test.js` (new): 10 detail-guard tests.
- `package.json`, `src/renderer/index.html`, `README.md`, `docs/STRICT_CLASSIFICATION_AND_QC.md`: version and operator guidance.

## Validation and limits

`npm run validate`: 61/61 automated tests pass on Node.js 22. Tests use synthetic OCR results and image buffers. Actual Windows portable EXE, live Rakuten image access, OCR quality on small captions, and end-to-end generation for real product rows are not verified in this environment. Manual checks should include ABY-70, ABY-71 and ADI-8 as well as any currently misclassified SKU.

The update requires the existing Node.js dependencies on the BUILD machine. Use `BUILD_PORTABLE.cmd` / `npm run build:portable` to build an EXE.
